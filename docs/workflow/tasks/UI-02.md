# UI-02: Test, typecheck and check scaffolding

- **Repo:** `frontforge-labs/ui`. **Tier:** routine. **Size:** M (100 to 200 changed lines).
- **Depends on:** UI-01.

## Objective

There are no unit tests: `vitest.config.ts` defines only the Storybook project, which runs stories
in Chromium through Playwright, and `"test": "vitest"` starts watch mode. Add a cheap,
deterministic, headless gate.

## Do

- Add a `unit` Vitest project (jsdom, `src/**/*.test.ts(x)`, a setup file importing
  `@testing-library/jest-dom/vitest`) next to the existing Storybook project, and add
  `@testing-library/user-event`.
- Scripts: `test` = `vitest run --project unit`; `test:stories` = the browser project;
  `typecheck` = `tsc --noEmit`; `check` = lint, then typecheck, then test, then build.
- Add `.nvmrc` (24) and `.github/workflows/check.yml` running `npm ci && npm run check`.
- First tests: `src/utils/cn.test.ts` (conflict merge, falsy inputs) and
  `src/utils/clipboard.test.ts` (`copyToClipboard` on both the Clipboard API and the
  `execCommand` fallback, mocked; plus `formatCSS`, `hexToRgb` and `rgbToHex`).

## Done when

`npm run check` exits 0 headless with no browser installed, and the new tests pass.

## Out of scope

Packaging (UI-03), component fixes, Storybook browser tests in `check`.

This repo has no `AGENTS.md`, so these are its conventions, taken from its `package.json`, its
configs and `REVIEW.md` on the `review-and-backlog` branch:

- React 19 and TypeScript, built with Vite or tsup; npm with the committed `package-lock.json`;
  Node 24.
- Match the existing style (Prettier defaults as configured, 2-space indent, ES modules).
- Change only what this packet asks. Note follow-ups instead of doing them.
- Install packages with `npm install -D <pkg>` so the lockfile stays in step; never hand-edit it.
- Nothing is pushed. Commit on the task branch only.
